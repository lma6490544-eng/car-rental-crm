## Локальный запуск

Требования: Node.js 22.12+, npm и запущенный Docker Desktop с Linux containers.

Из этой папки в PowerShell:

```powershell
# Только если .env ещё нет:
Copy-Item .env.example .env
npm.cmd ci
npm.cmd run db:up
npm.cmd run db:migrate
npm.cmd run admin:create
npm.cmd run dev
```

Не копируйте шаблон поверх существующего .env. Значения PostgreSQL в примере предназначены для локальной разработки и применяются при первой инициализации Docker volume.

Команда admin:create создаёт первого администратора один раз. По умолчанию логин admin, случайный пароль сохраняется в [.local/initial-admin.txt](.local/initial-admin.txt), исключённом из исходников. Повтор команды не меняет существующего администратора. Можно заранее задать ADMIN_LOGIN, ADMIN_FULL_NAME и ADMIN_PASSWORD через окружение процесса; при явном пароле файл не создаётся. Пароль не выводится в консоль.

- Приложение: http://127.0.0.1:5173
- Вход: http://127.0.0.1:5173/login
- Сотрудники (admin): http://127.0.0.1:5173/users
- Health: http://127.0.0.1:3001/api/v1/health
- Swagger (только development): http://127.0.0.1:3001/api/docs
- PostgreSQL: 127.0.0.1:15432

Frontend проксирует /api в backend. Сервисы слушают loopback. APP_ORIGINS перечисляет разрешённые адреса браузерного приложения; по умолчанию localhost и 127.0.0.1 на порту 5173. Для ручных изменяющих API-запросов нужны Origin, JSON, сессионная cookie и X-CSRF-Token из /auth/me. Создание/блокировка сотрудников также требуют Idempotency-Key. Пример контракта — [описание этапа](docs/stage-1.md).

## Проверка первого этапа

1. Войти администратором.
2. Открыть «Сотрудники», создать менеджера (пароль не короче 12 символов).
3. В отдельном профиле/приватном окне войти менеджером: /users должен показывать запрет доступа.
4. Администратором заблокировать менеджера. После обновления окна менеджера сессия завершится. Новый вход запрещён.
5. Разблокировать менеджера: нужен новый вход, старая сессия не восстанавливается.
6. Выйти и проверить, что /users снова требует вход.

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:stage1
npm.cmd run test:browser
```

Тесты используют реальную локальную PostgreSQL, создают отдельные базы crm_stage1_test_* / crm_stage1_ui_* и удаляют только их после завершения. Рабочая база не очищается. Пользователю PostgreSQL нужны права CREATE DATABASE. Браузерные проверки запускают временные API/Vite на свободных портах и headless Edge через Playwright. Для Chrome можно задать PLAYWRIGHT_CHANNEL=chrome. Скриншоты проверки пишутся в .runtime (не исходники). Дополнительный браузер не скачивается.

## Текущее устройство

- apps/web — React, Ant Design; /login, /, /users, /clients, /clients/:id, /fleet, /fleet/:id, /pricing, /calendar; страницы загружаются отдельно.
- apps/api — NestJS, Zod DTO, PostgreSQL-сессии, защита Origin/CSRF, обработка ошибок.
- apps/api/src/db/schema.ts и drizzle — таблицы и миграции 0000–0011, включая брони, расписание и финансовый журнал.
- apps/api/src/pricing — точные расчёты, версионируемый прайс и самостоятельные расчётные снимки этапа 3.
- apps/api/src/scheduling — бронирования, доступность, автоматический preview цены и технические блокировки.
- apps/api/src/catalog — клиенты, автомобили, справочники, DTO и тестовый seed.
- apps/web/src/catalog.tsx — общий polling, формы команд с восстановлением результата и история.
- apps/api/src/platform — транзакции команд, идемпотентность, аудит и защита запросов.
- apps/api/tests, apps/web/tests — интеграционные и браузерные проверки.
- docs/stage-1.md — реализованное поведение, проверки и ограничения.
- docs/implementation-plan.md — следующие этапы, требующие отдельного разрешения.

Задание outbox для письма бухгалтерии создаётся по выбору оператора при сохранении новой брони организации с назначенным автомобилем или по кнопке «Выставить счёт» в карточке такой брони. Назначение автомобиля само по себе письмо не запускает. Для включения отправки задайте на сервере API `ACCOUNTING_SMTP_APP_PASSWORD` и перезапустите API. По умолчанию отправитель — `mihaillgt@yandex.com`, получатель — `soforadc@gmail.com`. Адреса задаются через `ACCOUNTING_SMTP_USER` и `ACCOUNTING_EMAIL_TO`. API подключается к `smtp.yandex.com:465` через TLS. До включения отправки задания остаются в очереди.

## Остановка и ограничения

Ctrl+C в терминале npm run dev останавливает API и frontend. npm run db:down останавливает PostgreSQL с сохранением Docker volume. Не используйте down -v для обычной остановки.

Первый этап не является рабочим развёртыванием. HTTPS и инфраструктура пилота — отдельный этап; при NODE_ENV=production API требует HTTPS origins, включает Secure-cookie и отключает Swagger. Восстановление/смена пароля через UI и создание дополнительных администраторов не входят в этот этап.

Сборка предупреждает о крупном общем JS-chunk Ant Design; вход и пользователи выделены в отдельные маршруты, предупреждение не блокирует сборку.
