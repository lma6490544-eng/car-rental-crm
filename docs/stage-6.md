# Этап 6. Осмотры, приватные файлы и договоры

**Статус: реализован и закрыт пользователем.** В поставку вошли оформление, оплата и залог в процессе оформления и фактическая выдача. Завершение аренды, продление и замена после выдачи относятся к этапу 7.

Из брони оператор открывает отдельную карточку «Договор». Осмотр выдачи сохраняется редакциями с показаниями, снимком назначенной машины и ссылками на подтверждённые фото. Для осмотра приёмки есть серверная поддержка. Сквозной сценарий приёмки с фактическим завершением относится к этапу 7. Раздел «Документы» в карточке клиента показывает сохранённые сканы. Загрузка новых сканов отключена по умолчанию для MVP. В карточке отображаются актуальные договор и акт. Готовые документы открываются для печати из заголовков секций.

Акт печатается по утверждённому листу «акт» из книги «464 СX.xls». В PDF подставляются сохранённые данные осмотра, в том числе топливо от 0 до 8 делений. Печатные флажки комплектности и схема автомобиля оставлены для ручных отметок. Для новой отметки о бумажном подписании CRM проверяет готовую версию PDF акта.

## Оформление и выдача

Из контекстного меню брони выберите «Создать договор». В карточке есть разделы «Водитель», «Договор», «Акт» и «Оплата». В разделе «Договор» собраны условия аренды и действия с печатной формой. Оператор видит даты, ставку, оплачиваемые сутки и лимит из текущей редакции брони. Реквизиты клиента сохраняются в его карточке. Раздел «Водитель» использует те же поля, проверку и предзаполнение, что и редактирование клиента в его карточке. Для печати договора ФЛ фамилия и имя берутся из отдельных полей реквизитов. Отчество подставляется при наличии. Для договора ФЛ нужен телефон, данные паспорта, дата рождения, адрес регистрации и реквизиты ВУ. Если обязательные реквизиты сохранены, раздел «Водитель» открывается свёрнутым. Шаги слева раскрывают соответствующие разделы и прокручивают карточку к ним. У старых карточек пустые поля раздела «Водитель» предзаполняются из сохранённой строки ФИО в порядке «фамилия, имя, отчество» и записываются после подтверждения оператором. Изменения условий проходят через существующий редактор с серверным перерасчётом и создают новую редакцию брони. В редакторе условий договора доступны даты, пробег, цены и скидки. Реквизиты клиента редактируются в разделе «Водитель», автомобиль меняется в разделе «Акт». Договор формируется из сохранённых условий. Второй оператор параллельно сохраняет осмотр выдачи в разделе «Акт». КАСКО подтягивается из карточки машины. Сумма залога предзаполняется по тарифу, а после формирования договора подставляется из его снимка.

При нажатии «Выдать автомобиль» CRM проверяет актуальность PDF договора и акта выдачи, а затем вместе с выдачей сохраняет отметки о подписании обеих версий. Оплата и залог доступны с момента начала оформления. Для выдачи требуется положительная оплата при ненулевой цене и полное получение согласованного залога. При нулевой сумме соответствующая операция не нужна. Допускается частичная оплата аренды с остатком по договору. До выдачи разрешено обновлять условия и документы после поступлений. Отмена, перенос и смена автомобиля после поступлений требуют возврата или компенсации. После выдачи сохраняется отдельный факт передачи машины, а повторная выдача блокируется. В шахматке начатое оформление отмечено бейджем «Оформление». После выдачи полностью оплаченная аренда фиолетовая, аренда с остатком долга голубая.

## Сверка печатных форм

В договорах ФЛ и ЮЛ сверены название, реквизиты сторон, данные автомобиля, условия аренды, обеспечительный платёж, лимит пробега, КАСКО, включённый НДС и блок подписей. Форма ЮЛ содержит реквизиты организации, представителя и основание полномочий. Данные дополнительного водителя относятся к редакции договора. Суммы, ставки, даты и НДС берутся из сохранённого снимка CRM по ТЗ v1.1 и уточнениям Q11–Q12. Печатная вёрстка адаптирована под PDF A4. Excel используется как исходник полей и текста.

## Настройка тестового экземпляра

- Добавочные миграции `0012–0018` рассчитаны на схему после `0011`. Миграция `0018` привязывает новые акты к версии реквизитов клиента. Для прежних актов сравниваются сохранённые имя и подписант. Локальный экземпляр используется как тестовый стенд. Перед обновлением существующей базы сохраните резервную копию.
- `CRM_CUSTOMER_DOCUMENT_UPLOADS_ENABLED=true` включает загрузку документов клиента через API и кнопку в карточке. Настройка применяется при запуске API. Список и скачивание сохранённых файлов, а также загрузка фото осмотра доступны независимо от настройки.
- `CRM_PRIVATE_FILES_DIR` — абсолютный путь к закрытому каталогу вне публикуемых директорий. У процесса API должны быть права чтения, записи и удаления. На Windows права каталога задаются ACL. Worker использует подкаталоги `incoming` и `objects` на одном томе для атомарной публикации.
- `CRM_LESSOR_JSON` — JSON-объект со строками `name`, `requisites`, `signer` и `authority`. Эти поля задают реквизиты арендодателя, единственного подписанта и основание полномочий. Для разработки используйте синтетические значения.
- PDF рендерится в установленном Microsoft Edge. Для установленного Chrome задайте `CRM_PDF_BROWSER=chrome`. После ошибки генерации можно повторить то же задание из карточки договора.

## Защита файлов

Загрузки ограничены 8 МиБ на файл. Фото принимаются в JPEG/PNG, документы клиента — в JPEG/PNG/PDF. Загрузка проходит через проверку сессии, Origin и CSRF. Временный объект публикуется через outbox после фиксации метаданных. Готовый объект читается через закрытый маршрут с проверкой связи с бронью или клиентом и контрольной суммы. Содержимое клиентского PDF отдаётся вложением.

После готовности новой редакции worker удаляет устаревший PDF. Снимок, версия шаблона и сведения о подписи сохраняются. Закрытые маршруты печати по ID версии генерируют снятый с хранения PDF из сохранённых данных. Старые версии шаблонов нужно сохранять в приложении для повторной печати.

Для фото предусматривается `delete_after`. Доступ закрывается сервером по наступлению срока, затем worker удаляет объект и фиксирует удаление в метаданных. Этап 7 должен проставлять общий срок всем фото аренды по факту окончательного возврата. Порядок восстановления из резервной копии с учётом удалений и сроков хранения остальных документов согласуется для эксплуатации.
