## Согласованные доработки форм и обслуживания

Для автомобиля добавлена «Коробка»: automatic (АКПП) / manual (МКПП). Выбирается в форме, показывается в карточке, изменения отражаются в истории. Старые записи сохраняют NULL («Не указана») до выбора оператора. API проверяет допустимые значения, БД содержит CHECK; прежние клиенты API при пропуске поля не сбрасывают уже сохранённую коробку. Форма требует выбор при сохранении.

Поле нового порога ТО видно только при добавлении процедуры «ТО». Для ГРМ, развала-схождения и остальных процедур оно скрыто и исключено из запроса сохранения, даже если перед переключением было заполнено вручную.

У записей обслуживания доступно «Редактировать»: дата, название процедуры, пробег выполнения и пометка. PATCH `/vehicles/:id/service-records/:recordId` принимает эти поля и expectedVersion автомобиля. Изменение атомарно сохраняет аудит с прежними/новыми значениями, outbox и результат ключа `vehicles.service.update`; конкурентная устаревшая правка отклоняется. Автор первоначальной записи сохраняется, автор/время исправления видны в истории автомобиля. Текущий пробег и порог ТО при исправлении исторической процедуры не пересчитываются. В архиве редактирование недоступно.

Предзаполнение порога ТО: поле появляется только при выборе процедуры «ТО». Для процедуры «ТО» UI предлагает пробег выполнения +10 000 км (до ввода пробега — текущий пробег автомобиля +10 000). Значение редактируется; после ручной правки, включая очистку, автоматическое предложение его не перезаписывает. Другие процедуры сохраняют прежний порог и сами не запускают новый интервал ТО.

После обсуждения пользователь разрешил следующие изменения; они реализованы поверх исходного этапа 2:

- Удалены подпись о минимальной карточке, «необязательно» у VIN и информационная строка тарифа/бака из формы.
- Телефон клиента и представителя: +7 и 10 цифр, разрешены пробелы/скобки/дефисы, начальная 8 преобразуется в +7; пустой телефон допустим. Серия паспорта — 4 цифры, номер — 6, с проверкой в форме и API.
- Госномер: одна допустимая буква, три цифры, две буквы и регион из 2–3 цифр; регион вводится справа отдельно. Старые записи не перезаписываются: несоответствующий номер нужно исправить при редактировании. Новое тестовое заполнение использует допустимые номера.
- Марка и модель вводятся с подсказками и свободным текстом. Отсутствующие значения создаются автоматически только при сохранении автомобиля, в той же транзакции. Регистр/повторные пробелы не создают дублей; для новой модели обязательна существующая тарифная группа. Страница настройки справочников не добавлялась.
- Единая «Пометка» становится обязательной «Причиной неготовности / пометкой» при выключенной готовности. Для совместимости хранения используются прежние поля readiness_reason/issue_notes, но форма и карточка показывают одно поле; старые значения читаются без потери.
- Отдельный комментарий требуется только при корректировке пробега или порога ТО. История показывает исключительно изменившиеся значения.
- Вкладка «Обслуживание» содержит журнал выполненных процедур: дата, свободное название с подсказками, пробег при выполнении (может отсутствовать), пометка, автор. Записи сохраняются без редактирования/удаления; история карточки находится на отдельной вкладке.
- Пробег из Excel означает последнюю выполненную процедуру. Он не создаёт следующий интервал и не меняет текущий пробег сам по себе. Для одновременного обновления текущего пробега предусмотрен явный переключатель; новый порог общего ТО вводится отдельно и необязательно. Операция атомарная, с expectedVersion, аудитом, outbox и идемпотентностью.

Миграция `0002_stale_human_fly.sql` добавляет vehicle_service_records и индексы уникальности названий справочников без учёта регистра. Реальные API: GET/POST `/api/v1/vehicles/:id/service-records`; POST принимает `{expectedVersion, performedOn, procedure, mileageKm, note, updateMileage, nextMaintenanceDueKm?}`. GET возвращает `{items,total}` по 20 записей с параметром page. Поиск результата поддерживает команду `vehicles.service`.

Миграция 0002 применена локально. Расширенный тест этапа содержит 13 сценариев (14 записей runner вместе с группой): дополнительно проверяет телефон/паспорт/госномер, конкурентное добавление справочников, журнал с идемпотентностью и версиями, явное обновление пробега/ТО, создание новой модели и процедуры через браузер. ## Готовые сценарии

- `/clients`: поиск по имени/названию, телефону и ИНН; тип/блокировка, пагинация; список без паспортных и банковских реквизитов.
- `/clients/:id`: минимальное создание по имени/названию, анкеты ФЛ/ЮЛ, контакты, индикатор заполнения основных реквизитов, заметки с автором/датой/закрытием, блокировка с причиной, разблокировка и история. Тип клиента после создания фиксирован; тёзки не объединяются.
- `/fleet`: пять согласованных колонок, поиск по марке/модели/номеру/VIN, фильтры кузова/готовности/мойки/замечаний/ТО/архива, сортировка по модели/пробегу/остатку до ТО, пагинация.
- `/fleet/:id`: полная карточка, изменение пробега/порога ТО с причиной, готовность и причина неготовности, мойка/замечания, история и архивация. Кузов строго sedan/hatchback/compact_van/cargo_minibus, бак 40/40/40/80 л; тарифная группа зависит от модели, не кузова.
- История автомобиля сохраняет прежние/новые значения, автора, время и причину. История доступна страницами по 50 записей. Отображение времени — Europe/Moscow.
- Общий GET-опрос каждые 5 секунд, дополнительное чтение при focus/visibility/online; запросы одного экземпляра не перекрываются, скрытая вкладка/offline не накапливают очередь. Последние данные и черновик остаются при ошибке. При конфликте можно сравнить актуальную карточку и явно подтвердить сохранение своего ввода поверх новой версии.
- URL сохраняет фильтры, сортировку и страницу; память вкладки — прокрутку. После входа восстанавливаются прямые ссылки новых разделов. При потере ответа доступны проверка результата и повтор с прежним ключом. Автоматических повторов записи нет.

Блокировка — единственный доступный сейчас клиентский статусный тег. Аренды, залоги, штрафы, долги и файлы не подменяются фиктивными операциями; будущие вкладки недоступны. Обслуживание сейчас показывает историю изменения карточки. Приёмка, финансовые операции ТО/ремонта, осмотры/PDF, Pricing и бронирования относятся к следующим этапам.

Подсветка «Скоро ТО» — остаток до порога не более 1000 км; «ТО требуется» — остаток ≤0. Это локальный порог предупреждения, а не прогноз аренды/запрет брони. Заполненная анкета сама по себе не подтверждает готовность к выдаче: окончательная проверка документов появится на её этапе.

## Данные и транзакции

Применена миграция `apps/api/drizzle/0001_amused_baron_zemo.sql`: pricing_groups, vehicle_brands, vehicle_models, equivalence_groups, equivalence_group_models, customers, customer_notes, vehicles. Таблицы и записи авторизации сохранены.

Физическая модель этапа 2 отличается от целевой логической: реквизиты ФЛ/ЮЛ находятся в `customers.details` JSONB со строгими Zod-схемами; выдаются только в защищённой карточке. Аудит клиента хранит названия изменённых полей без копирования паспортных данных. История состояния автомобиля хранится в audit_logs; mileage_readings/readiness_events будут выделяться при добавлении источников осмотров/обслуживания.

Номер: верхний регистр, удаление пробелов/дефисов, замена визуально совпадающих русских АВЕКМНОРСТУХ латинскими, 3–15 символов A–Z/цифр. VIN: верхний регистр, без пробелов, 17 букв/цифр без I/O/Q; пустой → NULL. Уникальность номера и заполненного VIN обеспечивает БД, включая архив. Это выбранная реализация нормализации для этапа 2; исходное ТЗ не менялось.

Бизнес-команды доступны admin и manager; активность сессии повторно проверяется в транзакции. Управление сотрудниками остаётся только admin. Запись, аудит, outbox и результат ключа команды атомарны; изменения требуют expectedVersion. Worker не добавлялся.

## Реальные API

Префикс `/api/v1`, сессия для всех маршрутов; запись требует Origin, CSRF и Idempotency-Key.

| Метод и путь | Назначение |
| --- | --- |
| GET/POST `/customers` | Список / создание |
| GET/PATCH `/customers/:id` | Карточка / `{expectedVersion,data}` |
| POST `/customers/:id/block` | `{expectedVersion,reason}` |
| POST `/customers/:id/unblock` | `{expectedVersion}` |
| GET/POST `/customers/:id/notes` | Заметки / `{expectedVersion,text}` |
| POST `/customers/:id/notes/:noteId/resolve` | Закрытие с `{expectedVersion}` |
| GET `/customers/:id/history?page=1` | История клиента |
| GET/POST `/vehicles` | Список / создание |
| GET/PATCH `/vehicles/:id` | Карточка / `{expectedVersion,reason,data}` |
| POST `/vehicles/:id/archive` | `{expectedVersion,reason}` |
| GET `/vehicles/:id/history?page=1` | История автомобиля |
| GET `/vehicle-brands`, `/vehicle-models`, `/pricing-groups`, `/equivalence-groups` | Справочники |

Списки `{items,total}` по 20 записей: q/page; клиенты type/blocked; машины bodyType/state/archived/sort/order. История `{items,total}` по 50 записей. `/operations/by-key` поддерживает customers.create/update/block/unblock/note/resolve и vehicles.create/update/archive; результат доступен только автору. users.* остаются только для admin.

```powershell

npm.cmd run db:seed:stage2
npm.cmd run dev
```

Стабильные ID и ON CONFLICT DO NOTHING позволяют повторять заполнение без перезаписи карточек. Seed транзакционный, запрещён в production. Только справочники после сборки: `node apps/api/dist/catalog/seed.js` без `--demo`.

Миграция и тестовое заполнение выполнены локально. Постоянные dev-процессы не запускались: проверки используют временные API/Vite и завершают их. Пароль admin остаётся в `.local/initial-admin.txt` и не копируется в документы.
