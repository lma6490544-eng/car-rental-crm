# Этап 1 — основа приложения и авторизация

Дата: 12 ноября 2026 года. Объём соответствует первому этапу [плана](implementation-plan.md). Следующие этапы не начинались.

## Реализовано

- /login, защищённая оболочка /, /users для администратора; lazy routes, состояния загрузки, ошибок и потери связи, адаптация ПК/планшета/телефона.
- Единый API-клиент; сессионный секрет только в HttpOnly-cookie, не в localStorage. CSRF-токен хранится в памяти вкладки.
- Серверные роли admin/manager. Через /users создаётся только manager по fullName/login/password. Неизвестные DTO-поля, в том числе роль от браузера, отклоняются.
- Создание первого admin отдельной командой под транзакционной блокировкой; повтор не сбрасывает пароль. Доступ администратора защищён от блокировки через UI/API.
- Блокировка/разблокировка менеджера с expectedVersion, аудитом и отзывом всех его сессий. Разблокировка не оживляет отозванные сессии.
- Сессии на 12 часов, случайный 256-битный токен; в БД только хеш. Cookie HttpOnly, SameSite=Lax, Path=/; Secure при production. Выход отзывает серверную сессию.
- Пароли 12–128 символов, scrypt N=32768, r=8, p=3 с индивидуальной солью; параметры включены в сохранённый формат. Для отсутствующего пользователя выполняется такой же расчёт. Один из вариантов параметров [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt), выбранный для меньшего потребления памяти. Перед пилотом параметры повторно измеряются на целевой машине.
- Лимиты входа в PostgreSQL: 10 попыток на нормализованный логин и 100 на IP за окно 15 минут; успешный вход сбрасывает счётчик логина. Счётчик IP не сбрасывается. В локальном reverse proxy клиенты могут иметь общий IP; политику proxy для рабочего размещения согласуют на этапе эксплуатации.
- Origin allowlist для всех изменяющих запросов, включая login; CSRF для аутентифицированных команд; запросы только JSON с ограничением 32 КБ. Нет публичной регистрации.
- Ошибки code/message/details/requestId; сервер генерирует requestId. SQL, пароли, cookies и тела запросов не логируются. Cache-Control=no-store, nosniff, no-referrer, защита фреймов.
- Новые пользователи и изменение доступа: транзакция объединяет изменение, audit, событие outbox и результат ключа команды. Параллельные одинаковые команды сериализуются; повтор возвращает сохранённый результат; другой payload с тем же ключом даёт 409.
- Хеш отпечатка команды создания не содержит сырого пароля: пароль проходит отдельный scrypt с солью, связанной с областью команды.
- /operations/by-key возвращает только результат текущего администратора. При потере ответа UI сохраняет ключ и ввод в памяти вкладки, позволяет проверить результат/повторить отправку без нового сотрудника. Отсутствие результата пока не доказывает, что запрос не выполняется.
- Изменение статуса требует версии; конфликт показывает сообщение и перечитывает список. Повтор неизвестного результата использует прежний ключ.

## Таблицы первого этапа

users, sessions, audit_logs, idempotency_records, outbox_jobs, login_limits. Миграция: apps/api/drizzle/0000_aberrant_franklin_richards.sql. Бизнес-таблицы следующих этапов отсутствуют.

В команде повторно проверяется активность сотрудника и сессии под блокировкой, а не только в guard до транзакции. Все SQL-параметры передаются отдельно. Ограниченный повтор deadlock/serialization затрагивает всю транзакцию до внешних эффектов. Изменения защищены FK, уникальностью логина/токена/ключа операции и проверками ролей.

Outbox — только транзакционная основа, без активного потребителя событий. Очистка истёкших сессий/служебных записей и эксплуатационное обслуживание будут добавлены вместе с worker; это не влияет на проверку срока сессии при запросе.

## Реальные маршруты API

Все пути имеют префикс /api/v1.

| Метод и путь | Доступ и поведение |
| --- | --- |
| GET /health | Публичная проверка API/PostgreSQL |
| POST /auth/login | Origin + JSON; cookie, user, csrfToken, expiresAt |
| GET /auth/me | Активная сессия; безопасные поля user и csrfToken |
| POST /auth/logout | Сессия + Origin + CSRF; отзыв и очистка cookie |
| GET /admin/users | Только admin; список без паролей/хешей |
| POST /admin/users | Только admin; fullName/login/password, Idempotency-Key |
| PATCH /admin/users/:id/status | Только admin; isActive/expectedVersion, Idempotency-Key |
| GET /operations/by-key?command=users.create&key=… | Только автор-admin; подтверждённый результат |
| GET /operations/by-key?command=users.status&key=… | Аналогично для изменения доступа |

Коды ошибок: VALIDATION_ERROR, INVALID_CREDENTIALS, LOGIN_RATE_LIMITED, UNAUTHENTICATED, FORBIDDEN, CSRF_REJECTED, ORIGIN_REJECTED, LOGIN_ALREADY_EXISTS, VERSION_CONFLICT, IDEMPOTENCY_KEY_REUSED, OPERATION_NOT_FOUND, ADMIN_PROTECTED, INVALID_JSON, BODY_TOO_LARGE. Swagger доступен только вне production; изменяющие запросы из Swagger также требуют Origin/CSRF/ключ команды.

## Проверки и приёмка

Автоматические сценарии:

- HTTP + PostgreSQL: cookie/CSRF/Origin, роли, строгие DTO, конфликт логина, конкурентные повторы, поиск результата, откат при искусственной ошибке outbox, версии, блокировка/разблокировка, logout/expiry, лимит входа, безопасные ошибки JSON.
- Реальный браузер: глубокая ссылка /users без входа, вход admin, валидация формы, потерянный ответ на успешное создание и восстановление результата без дубля, запрет /users менеджеру, блокировка активной сессии, сетевой сбой/повтор, выход, мобильная ширина и отсутствие ошибок JS.
- TypeScript и production-сборка.

Результаты 12 ноября 2026: TypeScript прошёл; backend и frontend собираются; 10 серверных сценариев (11 записей Node test runner с родительской группой) и 4 браузерных сценария (5 записей с группой) прошли. Интеграционный прогон с scrypt p=3 занял около 8,4 с внутри тестовой группы; отдельный успешный вход около 0,24 с на локальной машине. Это не нагрузочные показатели пилота.

Проверены скриншоты страницы входа и списка сотрудников, а также мобильный вход 390×844 без горизонтального скролла. При проверке устранены нестабильное доступное имя кнопки повторной загрузки и стандартные несогласованные ответы на некорректный/слишком большой JSON. Сборка предупреждает о крупном общем JS-chunk Ant Design (около 772 КБ до gzip); это известное неблокирующее ограничение. Тесты создают только свои временные базы; credentials тестов случайны и не печатаются. 12 ноября 2026 года пользователь подтвердил завершение этапа авторизации. Этап 1 закрыт; начало этапа 2 требует отдельного разрешения.

## Что не включено

Общий опрос бизнес-данных раз в 5 секунд ещё не реализован: это согласованное решение MVP (Q17), которое подключается в соответствующих следующих этапах. В текущем auth.tsx есть только перепроверка сессии раз в 60 секунд для видимой вкладки и при focus. /users обновляется вручную и после действий. SSE отложен.

Нет клиентов, автопарка, расчёта тарифов, шахматки, бронирований, финансов, осмотров, PDF, email, загрузки/удаления фотографий или рабочего деплоя. Нет интерфейса смены/восстановления пароля, назначения admin и внешних провайдеров входа. Полноценные политики backup и очистки служебных записей — этап эксплуатации. Проверенный локальный запуск не означает готовность публичного размещения.
